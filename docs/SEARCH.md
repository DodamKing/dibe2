# 음원 검색

`GET /api/songs/search`의 전체·제목·가수·앨범 검색. 2026-11-08에 정규식 부분 일치를 검색 엔진으로 바꿨다.
가사·연령 게이트(관리자)는 예전 정규식 그대로다. 영상 탭 검색은 유튜브 결과라 이 엔진과 무관하다.

## 왜 바꿨나 (2026-11-08 실측)
예전: 제목·가수에 글자가 들어 있는지만 봤다(글자 사이 띄어쓰기 허용, 대소문자 무시). 정렬은 DB 순서.

| 검색어 | 예전 | 지금 |
|---|---|---|
| `ㅂㅍㅈ`·`ㅅㄴㅁㅎ` (초성) | 0 | 밤편지·소년만화 |
| `dkdldb`·`tkfkdgo` (한영 키 안 바꿈) | 0 | 아이유·사랑해 |
| `아이우`·`suprnatural` (오타) | 0 | 아이유·Supernatural |
| `꽃갈피`·`폭싹` (앨범) | 0 | 해당 앨범 곡 |
| `좋은 날` | DB 순서 | 아이유 〈좋은 날〉이 1위 |

## 구조
- `server/utils/searchText.js` — 순수 함수: `normalize`(소문자·글자/숫자만), `chosung`, `toJamo`(겹모음·겹받침까지 쪼갬), `engToKor`(두벌식), `fuzzyDistance`(부분 문자열 편집 거리)
- `server/services/searchService.js` — 색인과 점수. `songService.searchSong`이 type 이 all/title/artist/album 이면 여기로 넘긴다
- 테스트: `tests/search.test.mjs`

### 색인
- 함수 인스턴스 메모리에 곡 전체(제목·가수·앨범·재생 수·차트 등장)를 올린다. 1.4만 곡 — **처음 만들 때 약 3초**(로컬→Atlas 실측), 그 뒤 검색 4~20ms(오타 비교가 돌면 100~200ms)
- 10분 지나면 다시 만든다. 다시 만드는 동안은 이전 색인으로 답한다(첫 색인만 기다림). 곡은 하루 한 번(08:00 차트) 늘어난다
- 웹은 글자를 치기 시작하면 자동완성(`/suggest`)이 먼저 불려 색인을 만들기 시작한다 → 엔터 때는 대개 준비돼 있다
- **속도 방침(2026-11-08 사용자 합의)**: 미리 최적화하지 않는다. 배포 후 폰에서 콜드 스타트 첫 검색을 재 보고 느리면 ① 색인을 만드는 동안 첫 검색은 예전 정규식으로 답하기(몇 줄) → 그래도 느리면 ② 검색용 값을 DB에 한 문서로 미리 저장(1.4만 곡 대신 문서 하나 읽기). 3초는 로컬(집)→Atlas 실측이라 운영(같은 지역 추정)은 짧을 수 있다
- 결과 페이지의 곡만 DB에서 다시 읽어 응답한다(응답 모양 `{items, total, hasMore}` 그대로 + `fuzzy`) → **앱(dibe2-app)은 수정 없이 결과만 좋아진다**

### 점수
토큰(띄어쓰기로 나눈 검색어)마다 필드별 최고 점수를 고르고, **모든 토큰이 어딘가 맞아야** 결과에 든다.

| 맞는 방식 | 점수 |
|---|---|
| 정확 일치 / 앞부분 / 포함 | 100 / 80 / 60 |
| 초성 (검색어가 초성만일 때) 정확 / 앞부분 / 포함(4글자 이상만) | 70 / 55 / 45 |
| 한영 자판 변환본으로 맞음 | 위 점수 × 0.95 |
| 오타 (자모·글자 4~9 → 거리 1, 10+ → 2) | 30 − 8×거리 − 길이 차이(최대 10) |

- 필드 가중치: 제목·가수 1, 앨범 0.7
- 여러 단어면 붙여 쓴 전체("좋은 날" → "좋은날")가 한 필드에 그대로 있으면 그 점수의 절반을 더한다
- 인기: `log10(1+재생수)×3 + min(차트 등장, 50)×0.2` — 같은 점수대 안에서 순서를 가르는 정도
- 🔴 **오타 비교는 다른 방식으로 하나도 못 찾았을 때만**. "결과 10개 미만이면"으로 했더니 `밤편지`(정확 1곡)에 엉뚱한 18곡이 붙고 `아이우`가 943곡이 됐다
- 🔴 **초성 중간 일치는 4글자 이상만**. 허용하니 `ㅇㅇㅇ`이 715곡

### 별칭 (영↔한 가수 이름)
- **자동**: `아이유(IU)`처럼 한·영이 같이 적힌 가수명에서 서로를 묶는다(5,624곡이 이런 표기). 같은 가수의 다른 곡이 `IU`로만 적혀 있어도 `아이유`로 찾는다
- **안 되는 것**: 한쪽 이름으로만 저장된 가수 — `BTS`→방탄소년단, `뉴진스`→NewJeans(영문만 저장된 곡 2,518), `에스파`→aespa. **손으로 넣는 별칭 사전 + 관리자 화면은 다음 작업**(2026-11-08 사용자)

## 자동완성 API
`GET /api/songs/suggest?q=` → `{ artists: [{name, count, coverUrl}] (3), songs: [{_id, title, artist, coverUrl}] (5), fuzzy }`
- 색인에 표시용 값(제목·가수·커버)을 같이 들고 있어 **DB를 안 읽는다**(타이핑마다 불리므로)
- 가수 = 가수 필드로 맞은 곡을 가수명(원문)별로 묶어 최고 점수·곡 수 순. 같은 가수라도 표기가 다르면(`아이유(IU)`/`IU`) 따로 묶인다

## 웹 화면 (2026-11-08)
- `components/SearchSuggest.vue` — 검색창 아래 패널. 입력 전 = **최근 검색어**(지우기·전체 삭제), 입력 중 = **가수·곡 자동완성** + "전체 결과 보기". 0.18초 멈추면 요청, 늦게 온 옛 응답은 버린다. 키보드 ↑↓ Enter(부모 입력칸이 `onKey`로 넘김), Esc 닫기
  - 가수 → 결과 창 **가수 탭**으로 그 이름 / 곡 → **그 곡 하나 바로 재생**(검색 결과 줄 클릭과 같음) / 최근 검색어·전체 결과 → **전체 탭** 검색
  - 쓰는 곳: 데스크탑 헤더(드롭다운), 모바일 검색 막대(아래 패널), 검색 결과 창 입력칸(검색어를 고치는 중일 때만), 영상 탭(최근 검색어만 `:suggest="false"`)
- `components/HighlightText.vue` + `utils/highlight.js` — 맞은 글자 강조(띄어쓰기·기호·대소문자 무시). 초성·자판 변환·오타로 맞은 곡은 글자가 안 겹쳐 강조 없음. v-html 없이 조각으로
- `utils/recentSearches.js` — localStorage `dibe2_recent_search_music` / `_video`, 최대 10개. 저장 못 해도 검색은 된다
- 결과 창(`SearchResultsModal.vue`): **'전체' 탭이 기본**(제목·가수·앨범), 위에 **가수 칩**(suggest 의 가수), 곡 제목·가수 강조, `fuzzy`면 "정확히 맞는 곡이 없어 비슷한 결과" 안내, **결과 없음 → "유튜브 영상에서 찾아보기"**(`/video?q=` — 영상 탭이 받아 바로 검색)
- 검증 스크립트는 일회성(scratchpad)으로 돌렸다: 자동완성(초성·자판), 최근 검색어 저장·분리, ↓Enter, 가수 칩·강조, 오타 안내, 결과 없음→영상 탭, 모바일 — 14/14

## 고른 방식과 대안
- **직접 만든 메모리 색인**(채택): 1.4만 곡이면 충분히 빠르고, 한글 오타를 자모 단위로 비교할 수 있다(Atlas Search 퍼지는 글자 단위라 한글에 약함). 초성·자판 변환·별칭은 어느 쪽이든 직접 만들어야 했다
- Atlas Search: 오타·자동완성·한국어 분석기 내장이지만 위 이유 + Atlas에 묶임
- **하이브리드**(Atlas Search 에 정규화·초성·별칭 필드를 넣어 쓰기): 곡이 10배 넘게 늘면 검토. 지금 만든 검색용 값을 그대로 옮길 수 있다
- 인기 검색어: 사용자가 적어 의미 없음 — 안 함(2026-11-08 사용자)
